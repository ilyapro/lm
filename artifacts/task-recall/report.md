# Recorded-task recall: local comparison and delivery handoff

This is development evidence from one isolated, synthetic SQLite fixture, not an independent holdout or a production latency result. The baseline predates the storage change; the post-change run used the same committed runner, seed, six queries, oracle and `max_results=6` limit. Both runs used public `memory_recall`, followed by `memory_lookup` only when a relevant result was a snippet. No private query, content, node ID or database snapshot is included.

The oracle asks for the task-only fact on the short, contextual and explicitly scoped requests; the correction for the correction request; and the cross-project lesson for its request. It expects no relevant fact for the missing-knowledge request. A returned non-oracle item on that last request is not evidence of the requested knowledge.

## Mechanism, compatibility and cost

The change reuses the existing `nodes_fts` → `search_content` → BM25 candidate path. The FTS table now indexes the already stored `nodes.task` beside content, with the existing node insert/update triggers kept in step; opening an old format index rebuilds that derived index from stored rows. `procedure` and other context metadata are not indexed. The fixture does not duplicate its identifier in prose. No caller prelude, alias registry, new search service, global weight/threshold change or production query copy was added. Count: **one existing retrieval mechanism reused, zero new mechanisms, zero task-ID prose copies, one changed production path** (`src/living_memory/storage.py`); `src/living_memory/retrieval.py` is unchanged. For a caller who knows only the identifier, **one mandatory manual content-word reformulation is removed**. Full-body lookup remains necessary when the selected fact is a snippet.

The targeted `PYTHONPATH=src python3 -m pytest -q tests/test_retrieval_task.py tests/test_storage.py` passed (71 tests). The storage regression constructs an old-format FTS index, opens it through current `MemoryStore`, checks old row discovery without rewriting the source content, then checks new and edited task values and reopening. The public recall regression covers short/contextual unscoped queries, a same-task distractor, an identical task in another scope, explicit scope, decay and exclusion of procedure metadata. This is a local compatibility check against a synthetic old index, not a live database mutation. The normal root gate remains required; `SKIPPED` is not a pass.

A separate read-only SQLite backup of the existing local database was opened in scratch with current `MemoryStore` (the live source was untouched). Its old FTS table lacked `task`; the migrated copy gained it. Node, connection and recall-event counts were preserved; `PRAGMA quick_check` returned `ok`; and a pre-existing row's task token was present in the rebuilt task index. The copy was deleted after the check. This tests database opening and index migration, not the still-running service's loaded code.
